# 约定：大纲 = 看板，细节笔记 = 档案（变更卡法）

> 对应想法（做法三）：大纲只存**状态 + 引用**，细节笔记存**内容单点**；任何修改用**追加式变更卡**表达，不回改旧文本。

## 两条铁律

1. **内容改动 → 只改那篇细节笔记**，大纲不再重复这段内容，只留一个 `[[链接]]`。
2. **状态/进度/结论改动 → 在大纲追加一条变更卡，不覆盖旧那行。** 旧事实作为时间线永久保留。

## 变更卡模板

```markdown
- [日期] 主题：旧 → 新（影响：一句话）
  来源：变动发生在 [[某篇细节笔记]]
  状态：完成 / 进行中 / 待定
```

追加而非覆盖，Agent 的"事件抽取 / 树重建 / 断头检测"才能从时间线里复原每次改动的因果链——这与 DESIGN.md 的"已验证树只追加不自动重组、SafeWriter 只增不删 + 幂等"同构。

## 示例

假如细节笔记 `[[依赖-X-调研]]` 里结论改了：

```markdown
## 里程碑时间线
- [2026-09-01] 依赖 X 方案：原定 A → 改为 B（影响：启动阶段需验证 B 兼容性）
  来源：[[依赖-X-调研]]
  状态：完成
```

不要写成把上面旧行"原定 A"改写成"改为 B"——那样旧证据就丢了。
