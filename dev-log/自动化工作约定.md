# 自动化工作约定

> 生效日期：2026-09-01
> 适用范围：NoteAgent 每个可验收子步骤、垂直切片和已确认设计决策的落地。

## 目标

让代码、测试、进度看板和远程仓库保持同步，同时避免敏感信息、运行时产物和未完成代码被自动发布。

## 固定闭环

```text
完成可验收子步骤
→ 运行测试与验证
→ 检查 git diff / .gitignore
→ 更新 [[进度看板]]
→ 必要时新增详情文档
→ 只暂存本次相关文件
→ git commit
→ git push origin main
```

## 触发粒度

- 每个可验收的 M0 子步骤完成时触发，例如 M0-3、M0-4、M0-5。
- 一个垂直切片完成时触发。
- 一个已确认的设计决策落地时触发。
- 不因单个文件变动或未完成的中间状态自动提交。

## 测试与提交门禁

提交前至少执行：

```bash
uv run pytest
git diff --check
git status
git check-ignore .env .venv data logs .zcode .DS_Store
```

测试失败、实现未完成或发现敏感文件未被忽略时：不提交、不推送；在进度看板中记录阻塞原因。

## 看板维护

- `进度看板.md` 的当前焦点只保留真实的下一步任务。
- 里程碑时间线只增不改，历史完成项不删除、不覆盖。
- 每条完成记录包含：日期、阶段编号、完成内容、测试结果、详情文档和 commit。
- 设计或范围发生变化时，新增变更卡，不回改旧结论。

## 原子事件记录自动化

使用显式命令记录每个阶段完成或额外工作：

```bash
python scripts/record-progress.py \
  --event-id EVT-YYYY-MM-DD-XXX \
  --stage M6 \
  --title "事件标题" \
  --summary "单个事件的完成内容" \
  --status completed \
  --tests "pytest ...: N passed" \
  --commit <sha>
```

- 一个事件对应一个 `dev-log/EVT-...md` 原子文档，不把多个事件合并记录。
- `completed` 必须提供测试结果；阻塞或进行中事项必须如实标记。
- 脚本只追加看板，不覆盖历史；同一事件 ID 重复执行必须幂等。
- 脚本自动维护双向链接：看板 `来源：[[事件文档]]`，详情文档 `[[进度看板]]`。
- 文件写入使用临时文件和原子替换；只操作 `dev-log/`，不修改用户 Vault、原始笔记或运行时目录。
- 脚本不自动 commit/push；完成测试、diff 和忽略规则检查后，仍按本约定选择性提交。

## Git 安全边界

- 只暂存本次相关文件，禁止无选择性执行 `git add .`。
- 只推送当前项目的 `main` 分支：`git push origin main`。
- 禁止自动提交 `.env`、`.venv/`、`data/`、`logs/`、`.zcode/`、`.DS_Store`。
- 禁止 force push、删除远程分支、自动 reset。
- 新增重要文件/目录必须同步写入 `.gitignore`。
